# 913100 — 알려진 보안 스캐너 User-Agent 탐지

> **한 줄 요약**: 요청의 `User-Agent` 가 **알려진 스캐너 목록**(`scanners-user-agents.data`)에 매칭되면, CRS가 403으로 차단한다.

- **파일**: `REQUEST-913-SCANNER-DETECTION.conf` (line 38)
- **phase**: 1
- **action**: `block`, `capture`, `t:none`, `setvar:'tx.inbound_anomaly_score_pl1=+%{tx.critical_anomaly_score}'`
- **severity**: CRITICAL (점수 5)
- **paranoia level**: 1
- **검증**: [`tests/913100.sh`](tests/913100.sh) — **PASS**

## 무슨 룰인가 (쉬운 설명)

- `User-Agent` 헤더를 **알려진 스캐너 목록**과 비교한다.
- 목록은 룰 파일과 같은 폴더의 **`scanners-user-agents.data`** (245줄)에 있다.
  대표 항목: `sqlmap`, `nikto`, `nmap`, `nuclei`, `masscan`, `wpscan`, `gobuster`, `nessus`, `openvas`, `acunetix` …
- `@pmFromFile` 은 파일의 패턴들과 **부분 일치(패턴 매칭)** 를 검사한다. 즉 UA 안에 `sqlmap` 이라는
  문자열이 들어 있으면(`sqlmap/1.7.2#stable`) 매칭된다.
- CRS4는 스캐너를 "선량/악성"으로 나누지 않고, **널리 쓰이는 스캐너의 기본 UA** 를 한 목록으로 관리한다.
- 목록 **79개 항목별 설명**은 아래 「스캐너 목록(`scanners-user-agents.data`) 항목별 설명」 표 참고.

## 조건 → 동작

- **검사**: `REQUEST_HEADERS:User-Agent "@pmFromFile scanners-user-agents.data"`
- **매칭되면**:
  - `capture` 로 매칭된 조각을 `TX.0` 에 저장 (로그 `logdata` 에 표시)
  - `tx.inbound_anomaly_score_pl1` 에 **CRITICAL=5** 누적
  - phase 2 끝에서 `949110` 이 403 차단

## 공격 예제 및 실측

"스캐너의 기본 User-Agent로 요청"이 이 룰의 공격 예제다.

## 흐름 / 관계

```
요청 도착 (User-Agent: sqlmap/1.7.2)
  phase 1 · 901-INITIALIZATION (점수 변수 0으로 초기화)
  phase 1 · 913100 : UA 가 스캐너 목록에 매칭 → 점수 +5 (아직 차단 아님)
  phase 1 · 913013 : detection_pl(1) < 2 → END 로 점프 (PL2~4 구간 skip)
  phase 2 끝 · 949110 : 점수 5 >= 임계값 5 → 403 차단
```

- 실제 차단은 이 룰이 아니라 **`949110`(차단 평가)** 이 한다.
- PL 게이팅 룰([913011](../../modsecurity/paranoia-gating.md)~[913018](../../modsecurity/paranoia-gating.md))이 이 룰을 실행할지/건너뛸지 제어한다.

## 스코어 5는 어디서? / PL 게이트와의 관계

이 룰의 동작 라인은 다음이다.

```
setvar:'tx.inbound_anomaly_score_pl1=+%{tx.critical_anomaly_score}'
```

- **점수 5는 이 룰에 하드코딩된 값이 아니다.** `severity:'CRITICAL'` 에 매핑된
  **`tx.critical_anomaly_score`** 변수에서 온다. 이 변수는 기본값을
  [901140](../REQUEST-901-INITIALIZATION/901140.md) 이 **5** 로 설정한다.
  (`crs-setup.conf` 의 `900100` 으로 바꿀 수 있음)
- **이 룰이 실행되는 조건**은 `tx.detection_paranoia_level >= 1` 이다.
  이 룰은 파일의 **PL1 구간**에 있고, 앞의 게이팅 룰
  [913011](../../modsecurity/paranoia-gating.md)/[913012](../../modsecurity/paranoia-gating.md)(`@lt 1`)이 `END`로 점프하지 않을 때만 실행된다.
  (기본값 detection PL=1 이므로 실행됨. detection PL=0 이면 실행 안 됨)
- 점수가 쌓여도 이 룰 자체는 막지 않는다. phase 2 끝에서
  [949110](../REQUEST-949-BLOCKING-EVALUATION/README.md) 이
  `tx.inbound_anomaly_score_threshold`(기본 5) 와 비교해 **403** 을 낸다.

> 자세한 연결(점수/PL/차단): [../../modsecurity/score-and-paranoia.md](../../modsecurity/score-and-paranoia.md)

## 참고

- 스캐너 목록: `crs/rules/scanners-user-agents.data`
- `@pmFromFile`: 파일의 패턴과 **부분 일치** 검사(Aho-Corasick 계열). 정규식이 아님.
- 오탐 가능성: UA에 스캐너 이름이 들어간 정상 도구(예: 사내 스캐너, 일부 개발도구)도 걸릴 수 있음.
  필요하면 `SecRuleRemoveById 913100` 또는 예외 처리.
- 파일 전체 설명: [README.md](README.md)
