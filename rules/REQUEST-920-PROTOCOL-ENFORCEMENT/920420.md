# 920420 — Request content type is not allowed by policy

> **한 줄 요약**: 요청 헤더 'Content-Type' — 정규식 패턴 탐지 (체인 조건 1단계) [치명(CRITICAL)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 983)
- **phase**: 1
- **검사 대상(변수)**: `REQUEST_HEADERS:Content-Type` → 요청 헤더 'Content-Type'
- **조건(연산자)**: `@rx ^[^;\s]+`
- **체인 1단계**: `TX:content_type` `!@within %{tx.allowed_request_content_type}` → 트랜잭션 변수 'content_type'
- **심각도(severity)**: 치명(CRITICAL) → 점수 5
- **paranoia level**: 1
- **검증**: [`tests/920420.sh`](tests/920420.sh)

## 원본 룰

```apache
SecRule REQUEST_HEADERS:Content-Type "@rx ^[^;\s]+" \
    "id:920420,\
    phase:1,\
    block,\
    capture,\
    t:none,\
    msg:'Request content type is not allowed by policy',\
    logdata:'%{MATCHED_VAR}',\
    tag:'application-multi',\
    tag:'language-multi',\
    tag:'platform-multi',\
    tag:'attack-protocol',\
    tag:'paranoia-level/1',\
    tag:'OWASP_CRS',\
    tag:'OWASP_CRS/PROTOCOL-ENFORCEMENT',\
    tag:'capec/1000/255/153',\
    ver:'OWASP_CRS/4.30.0-dev',\
    severity:'CRITICAL',\
    setvar:'tx.content_type=|%{tx.0}|',\
    chain"
    SecRule TX:content_type "!@within %{tx.allowed_request_content_type}" \
        "t:lowercase,\
        setvar:'tx.inbound_anomaly_score_pl1=+%{tx.critical_anomaly_score}'"
```

## 무슨 룰인가 (쉬운 설명)

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `REQUEST_HEADERS:Content-Type` — 정규식 패턴에 매칭되면 탐지
  - 2단계: `TX:content_type` — 목록에 **없으면** 탐지

- **무엇을 보나**: 요청 헤더 'Content-Type' (`REQUEST_HEADERS:Content-Type`) **및** 체인 1단계 (`TX:content_type`)
- **어떻게 판단하나**: 정규식 패턴에 매칭되면 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 치명(CRITICAL) 등급으로 **점수 5** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).

## 정규식 / 패턴 해설

- **연산자 의미**: 정규식 패턴에 매칭되면 탐지
- **변환(transform)**: 없음 (`t:none`)

- **구조**: 시작 앵커 `^`
- **문자 클래스**: `[^;\s]`
- 단일 패턴 — 전체 정규식은 위 **조건(연산자)** 원문 참고.
