# 920340 — Content-Type header missing from request with non-zero Content-Length

> **한 줄 요약**: 요청 헤더 'Content-Length' — 형식 검증(불일치 탐지) (체인 조건 1단계) [치명(CRITICAL)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 712)
- **phase**: 1
- **검사 대상(변수)**: `REQUEST_HEADERS:Content-Length` → 요청 헤더 'Content-Length'
- **조건(연산자)**: `!@rx ^0$`
- **체인 1단계**: `&REQUEST_HEADERS:Content-Type` `@eq 0` → 요청 헤더 'Content-Type' 의 개수(존재 여부)
- **심각도(severity)**: 치명(CRITICAL) → 점수 5
- **paranoia level**: 1
- **검증**: [`tests/920340.sh`](tests/920340.sh)

## 원본 룰

```apache
SecRule REQUEST_HEADERS:Content-Length "!@rx ^0$" \
    "id:920340,\
    phase:1,\
    block,\
    t:none,\
    msg:'Content-Type header missing from request with non-zero Content-Length',\
    tag:'application-multi',\
    tag:'language-multi',\
    tag:'platform-multi',\
    tag:'attack-protocol',\
    tag:'paranoia-level/1',\
    tag:'OWASP_CRS',\
    tag:'OWASP_CRS/PROTOCOL-ENFORCEMENT',\
    tag:'capec/1000/210/272',\
    ver:'OWASP_CRS/4.30.0-dev',\
    severity:'CRITICAL',\
    chain"
    SecRule &REQUEST_HEADERS:Content-Type "@eq 0" \
        "t:none,\
        setvar:'tx.inbound_anomaly_score_pl1=+%{tx.critical_anomaly_score}'"
```

## 무슨 룰인가 (쉬운 설명)

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `REQUEST_HEADERS:Content-Length` — 정규식에 **매칭되지 않으면**(형식이 어긋나면) 탐지
  - 2단계: `&REQUEST_HEADERS:Content-Type` — `eq` 조건(값 `0`)에 맞으면 탐지

- **무엇을 보나**: 요청 헤더 'Content-Length' (`REQUEST_HEADERS:Content-Length`) **및** 체인 1단계 (`&REQUEST_HEADERS:Content-Type`)
- **어떻게 판단하나**: 정규식에 **매칭되지 않으면**(형식이 어긋나면) 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 치명(CRITICAL) 등급으로 **점수 5** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).

- **CWE**: CWE-444 / CWE-436
- **OWASP Top 10 2025**: 직접 대응 없음 (A02/A05 맥락)
- **CAPEC (CRS 태그)**: `capec/1000/210/272`

## 정규식 / 패턴 해설

- **연산자 의미**: 정규식에 **매칭되지 않으면**(형식이 어긋나면) 탐지
- **변환(transform)**: 없음 (`t:none`)

- **구조**: 시작 앵커 `^`, 끝 앵커 `$`
- 단일 패턴 — 전체 정규식은 위 **조건(연산자)** 원문 참고.
