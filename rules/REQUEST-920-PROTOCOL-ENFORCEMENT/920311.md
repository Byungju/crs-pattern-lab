# 920311 — Request Has an Empty Accept Header

> **한 줄 요약**: 요청 헤더 'Accept' — 정규식 패턴 탐지 (체인 조건 2단계) [알림(NOTICE)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 636)
- **phase**: 1
- **검사 대상(변수)**: `REQUEST_HEADERS:Accept` → 요청 헤더 'Accept'
- **조건(연산자)**: `@rx ^$`
- **체인 1단계**: `REQUEST_METHOD` `!@rx ^OPTIONS$` → HTTP 메서드
- **체인 2단계**: `&REQUEST_HEADERS:User-Agent` `@eq 0` → 요청 헤더 'User-Agent' 의 개수(존재 여부)
- **심각도(severity)**: 알림(NOTICE) → 점수 2
- **paranoia level**: 1
- **검증**: [`tests/920311.sh`](tests/920311.sh)

## 원본 룰

```apache
SecRule REQUEST_HEADERS:Accept "@rx ^$" \
    "id:920311,\
    phase:1,\
    block,\
    t:none,\
    msg:'Request Has an Empty Accept Header',\
    tag:'application-multi',\
    tag:'language-multi',\
    tag:'platform-multi',\
    tag:'attack-protocol',\
    tag:'paranoia-level/1',\
    tag:'OWASP_CRS',\
    tag:'OWASP_CRS/PROTOCOL-ENFORCEMENT',\
    tag:'capec/1000/210/272',\
    ver:'OWASP_CRS/4.30.0-dev',\
    severity:'NOTICE',\
    chain"
    SecRule REQUEST_METHOD "!@rx ^OPTIONS$" \
        "chain"
        SecRule &REQUEST_HEADERS:User-Agent "@eq 0" \
            "t:none,\
            setvar:'tx.inbound_anomaly_score_pl1=+%{tx.notice_anomaly_score}'"
```

## 무슨 룰인가 (쉬운 설명)

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `REQUEST_HEADERS:Accept` — 정규식 패턴에 매칭되면 탐지
  - 2단계: `REQUEST_METHOD` — 정규식에 **매칭되지 않으면**(형식이 어긋나면) 탐지
  - 3단계: `&REQUEST_HEADERS:User-Agent` — `eq` 조건(값 `0`)에 맞으면 탐지

- **무엇을 보나**: 요청 헤더 'Accept' (`REQUEST_HEADERS:Accept`) **및** 체인 2단계 (`REQUEST_METHOD, &REQUEST_HEADERS:User-Agent`)
- **어떻게 판단하나**: 정규식 패턴에 매칭되면 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 알림(NOTICE) 등급으로 **점수 2** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).
