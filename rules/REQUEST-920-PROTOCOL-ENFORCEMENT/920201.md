# 920201 — Range: Too many fields for pdf request (63 or more)

> **한 줄 요약**: 요청 파일명 — 문자열 일치 탐지 (체인 조건 1단계) [경고(WARNING)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 1443)
- **phase**: 1
- **검사 대상(변수)**: `REQUEST_BASENAME` → 요청 파일명
- **조건(연산자)**: `@endsWith .pdf`
- **체인 1단계**: `REQUEST_HEADERS:Range` `@rx ^bytes=(?:(?:\d+)?-(?:\d+)?\s*,?\s*){63}` → 요청 헤더 'Range'
- **심각도(severity)**: 경고(WARNING) → 점수 3
- **paranoia level**: 2
- **검증**: [`tests/920201.sh`](tests/920201.sh)

## 원본 룰

```apache
SecRule REQUEST_BASENAME "@endsWith .pdf" \

```

## 무슨 룰인가 (쉬운 설명)

**PDF 요청**에서 `Range` 범위 필드가 **63개 이상**이면 탐지한다(920200의 형제, `chain`). PDF 다운로더는 범위를 많이 쓰므로 임계값을 높게(63) 잡았고, 이를 넘는 과도한 Range는 **Range 요청 DoS(CVE-2011-3192)** 로 본다. 근거: CVE-2011-3192.

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `REQUEST_BASENAME` — 특정 문자열로 끝나면 탐지
  - 2단계: `REQUEST_HEADERS:Range` — 정규식 패턴에 매칭되면 탐지

- **무엇을 보나**: 요청 파일명 (`REQUEST_BASENAME`) **및** 체인 1단계 (`REQUEST_HEADERS:Range`)
- **어떻게 판단하나**: 특정 문자열로 끝나면 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 경고(WARNING) 등급으로 **점수 3** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).
