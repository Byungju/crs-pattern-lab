# 920370 — Argument value too long

> **한 줄 요약**: 트랜잭션 변수 'ARG_LENGTH' 의 개수(존재 여부) — 값 비교 탐지 (체인 조건 1단계) [치명(CRITICAL)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 843)
- **phase**: 2
- **검사 대상(변수)**: `&TX:ARG_LENGTH` → 트랜잭션 변수 'ARG_LENGTH' 의 개수(존재 여부)
- **조건(연산자)**: `@eq 1`
- **체인 1단계**: `ARGS` `@gt %{tx.arg_length}` → 파라미터(인자) 값
- **심각도(severity)**: 치명(CRITICAL) → 점수 5
- **paranoia level**: 1
- **검증**: [`tests/920370.sh`](tests/920370.sh)

## 원본 룰

```apache
SecRule &TX:ARG_LENGTH "@eq 1" \
    "id:920370,\
    phase:2,\
    block,\
    t:none,\
    msg:'Argument value too long',\
    logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}',\
    tag:'application-multi',\
    tag:'language-multi',\
    tag:'platform-multi',\
    tag:'attack-protocol',\
    tag:'paranoia-level/1',\
    tag:'OWASP_CRS',\
    tag:'OWASP_CRS/PROTOCOL-ENFORCEMENT',\
    tag:'capec/1000/210/272',\
    ver:'OWASP_CRS/4.30.0-dev',\
    severity:'CRITICAL',\
    chain"
    SecRule ARGS "@gt %{tx.arg_length}" \
        "t:none,t:length,\
        setvar:'tx.inbound_anomaly_score_pl1=+%{tx.critical_anomaly_score}'"
```

## 무슨 룰인가 (쉬운 설명)

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `&TX:ARG_LENGTH` — `eq` 조건(값 `1`)에 맞으면 탐지
  - 2단계: `ARGS` — `gt` 조건(값 `%{tx.arg_length}`)에 맞으면 탐지

- **무엇을 보나**: 트랜잭션 변수 'ARG_LENGTH' 의 개수(존재 여부) (`&TX:ARG_LENGTH`) **및** 체인 1단계 (`ARGS`)
- **어떻게 판단하나**: `eq` 조건(값 `1`)에 맞으면 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 치명(CRITICAL) 등급으로 **점수 5** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).
