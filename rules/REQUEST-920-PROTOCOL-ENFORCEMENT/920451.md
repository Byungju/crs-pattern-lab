# 920451 — HTTP header is restricted by policy (%{MATCHED_VAR})

> **한 줄 요약**: 요청 헤더 — 정규식 패턴 탐지 (체인 조건 1단계) [치명(CRITICAL)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 1560)
- **phase**: 1
- **검사 대상(변수)**: `REQUEST_HEADERS_NAMES` → 요청 헤더
- **조건(연산자)**: `@rx ^.*$`
- **체인 1단계**: `TX:/^header_name_920451_/` `@within %{tx.restricted_headers_extended}` → 트랜잭션 변수 '/^header_name_920451_/'
- **심각도(severity)**: 치명(CRITICAL) → 점수 5
- **paranoia level**: 2
- **검증**: [`tests/920451.sh`](tests/920451.sh)

## 원본 룰

```apache
SecRule REQUEST_HEADERS_NAMES "@rx ^.*$" \
    "id:920451,\
    phase:1,\
    block,\
    capture,\
    t:none,t:lowercase,\
    msg:'HTTP header is restricted by policy (%{MATCHED_VAR})',\
    logdata:'Restricted header detected: %{MATCHED_VAR}',\
    tag:'application-multi',\

    tag:'platform-multi',\

    tag:'capec/1000/210/272',\
    ver:'OWASP_CRS/4.30.0-dev',\
    severity:'CRITICAL',\
    setvar:'tx.header_name_920451_%{tx.0}=/%{tx.0}/',\
    chain"
    SecRule TX:/^header_name_920451_/ "@within %{tx.restricted_headers_extended}" \
        "setvar:'tx.inbound_anomaly_score_pl2=+%{tx.critical_anomaly_score}'"
```

## 무슨 룰인가 (쉬운 설명)

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `REQUEST_HEADERS_NAMES` — 정규식 패턴에 매칭되면 탐지
  - 2단계: `TX:/^header_name_920451_/` — 목록 안에 있으면 탐지

- **무엇을 보나**: 요청 헤더 (`REQUEST_HEADERS_NAMES`) **및** 체인 1단계 (`TX:/^header_name_920451_/`)
- **어떻게 판단하나**: 정규식 패턴에 매칭되면 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 치명(CRITICAL) 등급으로 **점수 5** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).

## 정규식 / 패턴 해설

- **연산자 의미**: 정규식 패턴에 매칭되면 탐지
- **변환(transform)**: `t:lowercase` (비교 전에 적용)

- **구조**: 시작 앵커 `^`, 끝 앵커 `$`
- 단일 패턴 — 전체 정규식은 위 **조건(연산자)** 원문 참고.
