## 무슨 룰인가 (쉬운 설명)

multipart/form-data 업로드의 **폼 필드 이름(`FILES_NAMES`)과 파일명(`FILES`)** 을 검사한다. 두 값에 허용 문자셋(정규식)을 벗어나는 문자(따옴표 `"`, 세미콜론 `;`, 역슬래시 `\` 등)가 섞이면 **multipart 파싱을 우회하려는 시도**로 보고 차단한다. 예: `filename="a;b.txt"` 로 업로드하면 HTTP 403.

- **무엇을 보나**: 업로드 파일명(filename) + 업로드 폼 필드 이름 (`FILES|FILES_NAMES`)
- **어떻게 판단하나**: 정규식에 **매칭되지 않으면**(형식이 어긋나면) 탐지
- **매칭되면**: 치명(CRITICAL) 등급으로 **점수 5** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).

## 정규식 / 패턴 해설

- **연산자 의미**: 정규식에 **매칭되지 않으면**(형식이 어긋나면) 탐지
- **변환(transform)**: `t:urlDecodeUni` (비교 전에 적용)

**정규식 분해** — 패턴은 `^(?: … )*$` 구조로, 문자열 **전체**가 아래 조각들의 반복으로만 구성돼야 한다. 벗어나면 `!@rx` 가 매칭되어 탐지된다. (정본: `regex-assembly/920120.ra`)

- `(?i)` : 대소문자 무시
- `^` … `$` : **전체 일치**(부분 일치 아님)
- `(?: … )*` : 안쪽 조각을 **0회 이상** 반복

조각은 크게 **두 종류**다.

**① HTML 엔티티** `&( … );` — 자주 쓰는 것만 선별해 허용:
- acute: `&aacute;` `&eacute;` `&iacute;` `&oacute;` `&uacute;` `&cacute;` `&nacute;` `&sacute;` `&zacute;` `&gacute;` `&lacute;` `&racute;`
- caron: `&ccaron;` `&dcaron;` `&ecaron;` `&lcaron;` `&ncaron;` `&rcaron;` `&scaron;` `&tcaron;` `&zcaron;`
- cedil: `&ccedil;` `&gcedil;` `&kcedil;` `&lcedil;` `&ncedil;` `&rcedil;` `&scedil;` `&tcedil;`
- circ: `&acirc;` `&ccirc;` `&ecirc;` `&gcirc;` `&hcirc;` `&icirc;` `&jcirc;` `&ocirc;` `&scirc;` `&ucirc;` `&wcirc;` `&ycirc;`
- grave: `&agrave;` `&egrave;` `&igrave;` `&ograve;` `&ugrave;`
- ring: `&aring;` `&uring;`
- tilde: `&atilde;` `&itilde;` `&ntilde;` `&otilde;`
- uml: `&auml;` `&euml;` `&iuml;` `&ouml;` `&uuml;` `&yuml;`
- 기타: `&amp;` `&apos;` `&nbsp;` `&oslash;`

**② 일반 문자** `[^"';=\x5c]` — `"` `'` `;` `=` `\` 를 **제외한** 모든 문자 1개.

**금지(탐지 유발) 문자** — 엔티티 밖에 나타나면 multipart 우회 시도로 본다:
- `"` : `filename="..."` 의 따옴표 경계를 깨뜨림
- `;` `=` : `name=value; …` 파라미터 구분자를 조작
- `\` : 이스케이프를 조작

`t:urlDecodeUni` 를 **먼저** 적용하므로, `%22`(=`"`)처럼 인코딩한 우회도 디코드 후 탐지된다.
