# 920180 — POST without Content-Length and Transfer-Encoding headers

> **한 줄 요약**: 요청 프로토콜(HTTP 버전 토큰) — 목록 제외 탐지 (체인 조건 3단계) [경고(WARNING)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 240)
- **phase**: 1
- **검사 대상(변수)**: `REQUEST_PROTOCOL` → 요청 프로토콜(HTTP 버전 토큰)
- **조건(연산자)**: `!@within HTTP/2 HTTP/2.0 HTTP/3 HTTP/3.0`
- **체인 1단계**: `REQUEST_METHOD` `@streq POST` → HTTP 메서드
- **체인 2단계**: `&REQUEST_HEADERS:Content-Length` `@eq 0` → 요청 헤더 'Content-Length' 의 개수(존재 여부)
- **체인 3단계**: `&REQUEST_HEADERS:Transfer-Encoding` `@eq 0` → 요청 헤더 'Transfer-Encoding' 의 개수(존재 여부)
- **심각도(severity)**: 경고(WARNING) → 점수 3
- **paranoia level**: 1
- **검증**: [`tests/920180.sh`](tests/920180.sh)

## 무슨 룰인가 (쉬운 설명)

HTTP/1.x **POST 요청에 `Content-Length`와 `Transfer-Encoding`이 둘 다 없을 때**를 탐지한다. 본문 길이를 알 수 없어 프록시·서버가 경계를 다르게 잡을 수 있고, 이는 **HTTP Request Smuggling(요청 밀수)** 의 전제가 된다(HTTP/2·HTTP/3는 프레임 길이로 결정되어 제외). 근거: CWE-444, `capec/1000/210/272`. 개념: [Request Smuggling](../../modsecurity/request-smuggling.md)

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `REQUEST_PROTOCOL` — 목록에 **없으면** 탐지
  - 2단계: `REQUEST_METHOD` — 문자열과 정확히 같으면 탐지
  - 3단계: `&REQUEST_HEADERS:Content-Length` — `eq` 조건(값 `0`)에 맞으면 탐지
  - 4단계: `&REQUEST_HEADERS:Transfer-Encoding` — `eq` 조건(값 `0`)에 맞으면 탐지

- **무엇을 보나**: 요청 프로토콜(HTTP 버전 토큰) (`REQUEST_PROTOCOL`) **및** 체인 3단계 (`REQUEST_METHOD, &REQUEST_HEADERS:Content-Length, &REQUEST_HEADERS:Transfer-Encoding`)
- **어떻게 판단하나**: 목록에 **없으면** 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 경고(WARNING) 등급으로 **점수 3** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).
