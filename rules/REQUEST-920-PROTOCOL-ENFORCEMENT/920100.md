## 무슨 룰인가 (쉬운 설명)

- **무엇을 보나**: HTTP 요청 첫 줄(메서드·경로·버전) (`REQUEST_LINE`)
- **어떻게 판단하나**: 정규식에 **매칭되지 않으면**(형식이 어긋나면) 탐지
- **매칭되면**: 경고(WARNING) 등급으로 **점수 3** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).

## 분류 / 근거 (OWASP·CWE·CAPEC)

- **공격 분류**: Protocol Abuse (요청 스머글링·프로토콜 조작 등)
- **CWE**: CWE-444 / CWE-436
- **OWASP Top 10 2025**: 직접 대응 없음 (A02/A05 맥락)
- **CAPEC (CRS 태그)**: `capec/1000/210/272`
- **분류·근거 문서**: [공격 분류 개요](../../modsecurity/attack-classes.md)

## 정규식 / 패턴 해설

- **연산자 의미**: 정규식에 **매칭되지 않으면**(형식이 어긋나면) 탐지
- **변환(transform)**: 없음 (`t:none`)

요청 첫 줄이 **RFC가 허용하는 형식**인지 검사한다(`!@rx` → 형식에 맞지 않으면 탐지).
- 허용 형식: `CONNECT host:port`, `OPTIONS *`, 또는 `메서드 경로 HTTP버전`
- 메서드는 **3~10자**(`[a-z]{3,10}`), 버전 토큰은 `[.-9A-Za-z]+`
- 즉 **메서드가 11자 이상**이거나 요청 줄 구조가 RFC와 어긋나면 매칭된다.
- 예: `TOOLONGMETHODX / HTTP/1.1`(메서드 13자) → 매칭 → 403
