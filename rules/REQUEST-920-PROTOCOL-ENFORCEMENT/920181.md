# 920181 — Content-Length and Transfer-Encoding headers present

> **한 줄 요약**: 요청 헤더 'Transfer-Encoding' 의 개수(존재 여부) — 값 비교 탐지 (체인 조건 1단계) [경고(WARNING)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 272)
- **phase**: 1
- **검사 대상(변수)**: `&REQUEST_HEADERS:Transfer-Encoding` → 요청 헤더 'Transfer-Encoding' 의 개수(존재 여부)
- **조건(연산자)**: `!@eq 0`
- **체인 1단계**: `&REQUEST_HEADERS:Content-Length` `!@eq 0` → 요청 헤더 'Content-Length' 의 개수(존재 여부)
- **심각도(severity)**: 경고(WARNING) → 점수 3
- **paranoia level**: 1
- **검증**: [`tests/920181.sh`](tests/920181.sh)

## 무슨 룰인가 (쉬운 설명)

**`Content-Length`와 `Transfer-Encoding` 헤더가 동시에 존재할 때**를 탐지한다(`chain`). RFC 7230 §3.3.2는 TE가 있으면 CL을 보내지 말라고, §3.3.3은 TE가 있으면 CL을 무시하라고 규정한다. 이를 어긴 요청은 **HTTP Request Smuggling(요청 밀수, HTTP Desync)** 의 대표 단서다(CL.TE / TE.CL / TE.TE). 근거: CWE-444, `capec/1000/210/272`, RFC 7230·RFC 9112 §6.1. CVE 예시: CVE-2019-16869(Netty), CVE-2020-8287(Node.js), CVE-2021-40346(HAProxy). 개념: [Request Smuggling](../../modsecurity/request-smuggling.md)

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `&REQUEST_HEADERS:Transfer-Encoding` — `eq` 조건(값 `0`)에 맞지 **않으면** 탐지
  - 2단계: `&REQUEST_HEADERS:Content-Length` — `eq` 조건(값 `0`)에 맞지 **않으면** 탐지

- **무엇을 보나**: 요청 헤더 'Transfer-Encoding' 의 개수(존재 여부) (`&REQUEST_HEADERS:Transfer-Encoding`) **및** 체인 1단계 (`&REQUEST_HEADERS:Content-Length`)
- **어떻게 판단하나**: `eq` 조건(값 `0`)에 맞지 **않으면** 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 경고(WARNING) 등급으로 **점수 3** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).
