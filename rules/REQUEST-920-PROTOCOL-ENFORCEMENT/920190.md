# 920190 — Range: Invalid Last Byte Value

> **한 줄 요약**: 요청 헤더 'Range' — 정규식 패턴 탐지 (체인 조건 1단계) [경고(WARNING)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 309)
- **phase**: 1
- **검사 대상(변수)**: `REQUEST_HEADERS:Range` → 요청 헤더 'Range'
- **조건(연산자)**: `@rx (\d+)-(\d+)`
- **체인 1단계**: `TX:2` `@lt %{tx.1}` → 트랜잭션 변수 '2'
- **심각도(severity)**: 경고(WARNING) → 점수 3
- **paranoia level**: 1
- **검증**: [`tests/920190.sh`](tests/920190.sh)

## 원본 룰

```apache
SecRule REQUEST_HEADERS:Range "@rx (\d+)-(\d+)" \
    "id:920190,\
    phase:1,\
    block,\
    capture,\
    t:none,\
    msg:'Range: Invalid Last Byte Value',\
    logdata:'%{MATCHED_VAR}',\
    tag:'application-multi',\
    tag:'language-multi',\
    tag:'platform-multi',\
    tag:'attack-protocol',\
    tag:'paranoia-level/1',\
    tag:'OWASP_CRS',\
    tag:'OWASP_CRS/PROTOCOL-ENFORCEMENT',\
    tag:'capec/1000/210/272',\
    ver:'OWASP_CRS/4.30.0-dev',\
    severity:'WARNING',\
    chain"
    SecRule TX:2 "@lt %{tx.1}" \
        "setvar:'tx.inbound_anomaly_score_pl1=+%{tx.warning_anomaly_score}'"
```

## 무슨 룰인가 (쉬운 설명)

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `REQUEST_HEADERS:Range` — 정규식 패턴에 매칭되면 탐지
  - 2단계: `TX:2` — `lt` 조건(값 `%{tx.1}`)에 맞으면 탐지

- **무엇을 보나**: 요청 헤더 'Range' (`REQUEST_HEADERS:Range`) **및** 체인 1단계 (`TX:2`)
- **어떻게 판단하나**: 정규식 패턴에 매칭되면 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 경고(WARNING) 등급으로 **점수 3** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).
