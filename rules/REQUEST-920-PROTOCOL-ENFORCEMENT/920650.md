# 920650 — HTTP method override attempt via _method parameter

> **한 줄 요약**: 트랜잭션 변수 'allow_method_override_parameter' — 값 비교 탐지 (체인 조건 2단계) [치명(CRITICAL)]

- **파일**: `REQUEST-920-PROTOCOL-ENFORCEMENT.conf` (line 1639)
- **phase**: 2
- **검사 대상(변수)**: `TX:allow_method_override_parameter` → 트랜잭션 변수 'allow_method_override_parameter'
- **조건(연산자)**: `@eq 0`
- **체인 1단계**: `REQUEST_METHOD` `!@streq %{ARGS._method}` → HTTP 메서드
- **체인 2단계**: `ARGS:_method` `@rx ^[a-z]{3,10}$` → 파라미터(인자) 값
- **심각도(severity)**: 치명(CRITICAL) → 점수 5
- **paranoia level**: 2
- **검증**: [`tests/920650.sh`](tests/920650.sh)

## 원본 룰

```apache
SecRule TX:allow_method_override_parameter "@eq 0" \
    "id:920650,\

    msg:'HTTP method override attempt via _method parameter',\
    logdata:'Requested method override: %{ARGS._method}',\
    tag:'application-multi',\

    severity:'CRITICAL',\
    chain"
    SecRule REQUEST_METHOD "!@streq %{ARGS._method}" \
        "t:none,t:lowercase,\
        chain"
        SecRule ARGS:_method "@rx ^[a-z]{3,10}$" \
            "t:none,t:urlDecodeUni,t:lowercase,\
            setvar:'tx.inbound_anomaly_score_pl2=+%{tx.critical_anomaly_score}'"
```

## 무슨 룰인가 (쉬운 설명)

- **`chain` 룰**: 아래 단계가 **모두 참일 때만** 매칭된다(AND).
  - 1단계: `TX:allow_method_override_parameter` — `eq` 조건(값 `0`)에 맞으면 탐지
  - 2단계: `REQUEST_METHOD` — 문자열과 다르면 탐지
  - 3단계: `ARGS:_method` — 정규식 패턴에 매칭되면 탐지

- **무엇을 보나**: 트랜잭션 변수 'allow_method_override_parameter' **및** 체인 2단계 (`REQUEST_METHOD, ARGS:_method`)
- **어떻게 판단하나**: `eq` 조건(값 `0`)에 맞으면 탐지 (모든 체인 단계가 참일 때)
- **매칭되면**: 치명(CRITICAL) 등급으로 **점수 5** 를 누적한다 (실제 403 차단은 `949110`(요청) / `959110`(응답)이 담당).
