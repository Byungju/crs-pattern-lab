# 905110 — Apache internal dummy connection 예외

- **파일**: `REQUEST-905-COMMON-EXCEPTIONS.conf` (line 38)
- **phase**: 1
- **action**: `pass`, `nolog` → chain → `ctl:ruleRemoveByTag=OWASP_CRS`, `ctl:auditEngine=Off`
- **로그**: 없음(nolog)
- **검증**: [`tests/905110.sh`](tests/905110.sh) — **PASS**

## 룰 원문

```
SecRule REMOTE_ADDR "@ipMatch 127.0.0.1,::1" \
    "id:905110, phase:1, pass, t:none, nolog, ... chain"
    SecRule REQUEST_HEADERS:User-Agent "@endsWith (internal dummy connection)" \
        "t:none, chain"
        SecRule REQUEST_LINE "@rx ^(?:GET /|OPTIONS \*) HTTP/[12]\.[01]$" \
            "t:none, ctl:ruleRemoveByTag=OWASP_CRS, ctl:auditEngine=Off"
```

## 의도

Apache 가 내부적으로 보내는 **internal dummy connection**(자체 헬스체크)을 오탐 없이 통과시키기 위해,
아래 3조건을 모두 만족하면 CRS 룰 전체를 제거하고 audit 을 끈다.

## 조건 (3개 모두 충족, chain)

| # | 대상 | 조건 |
|---|------|------|
| 1 | `REMOTE_ADDR` | `@ipMatch 127.0.0.1,::1` |
| 2 | `REQUEST_HEADERS:User-Agent` | `@endsWith (internal dummy connection)` |
| 3 | `REQUEST_LINE` | `@rx ^(?:GET /\|OPTIONS \*) HTTP/[12]\.[01]$` |

## 동작

- `ctl:ruleRemoveByTag=OWASP_CRS` → 이 트랜잭션에서 CRS 룰 전체 비활성
- `ctl:auditEngine=Off` → 이 트랜잭션 audit 로그 비활성

## 검증 (920350 을 표식으로 사용)

`Host: 127.0.0.1`(numeric) 요청은 정상 시 CRS 룰 **920350**("Host header is a numeric IP address")을
발생시킨다. 예외가 적용되면 이 룰이 제거되어 920350 이 사라지므로, 이를 관찰한다.

| 시나리오 | UA | path | 920350 | audit | 결과 |
|----------|----|----|--------|-------|------|
| 트리거 | `Apache (internal dummy connection)` | `/` | **0** | **0** | PASS |
| 대조군1 | `Apache (internal dummy connection)` | `/x` | 1 | 1 | PASS |
| 대조군2 | `Apache` | `/` | 1 | 1 | PASS |

```
./tests/905110.sh
PASS 905110 트리거: CRS 제거(920350 사라짐)
PASS 905110 트리거: auditEngine=Off(audit 미기록)
PASS 905110 대조군1: REQUEST_LINE 불일치 → 예외 미적용(920350=1)
PASS 905110 대조군2: UA 불일치 → 예외 미적용(920350=1)
```

## 배경: 왜 이 룰이 기본 포함되어 있나

- **대상**: Apache 가 내부적으로 자기 자신에게 보내는 **internal dummy connection**.
  Apache 는 (재)기동/graceful restart 등에서 자체 웹서버 연결을 확인하기 위해
  `User-Agent: ... (internal dummy connection)` 형태의 요청을 로컬로 보낸다. 이 요청을
  오탐 없이 통과시키려는 예외 룰이다.
- **기원**: 905100 과 같은 계열로 `base_rules/REQUEST-01-COMMON-EXCEPTIONS.conf`(2014, Ryan Barnett)에서
  시작했고, 룰 id 가 `901110 → 905110` 으로 재번호되었다.
- **HTTP/2 확장 이력**: CHANGES 에 `Extended 905100 and 905110 for HTTP/2.0`(Christoph Hansen) 기록이 있다.
  현재 `REQUEST_LINE` 정규식 `^(?:GET /|OPTIONS \*) HTTP/[12]\.[01]$` 는
  `HTTP/1.0`, `HTTP/1.1`, `HTTP/2.0`, `HTTP/2.1` 을 포함한다.
- **CRS 다중 엔진/플랫폼 공용 룰셋**: Apache(v2)와 nginx(v3) 등이 같은 룰을 공유한다.
  905110 은 `REQUEST_LINE` 을 **프로토콜까지 포함**해 매칭하므로, 905100 과 달리
  nginx + libmodsecurity v3 에서도 **정상 발동**한다.
- **기본 제공 이유**: 공용 룰 / 로컬(`127.0.0.1`,`::1`) 한정이라 안전 / 룰 ID 하위호환 /
  오탐 완화 목적이라 제거할 실익이 적다. (905100 과 동일한 맥락)

## 참고

- 905110 은 `REQUEST_LINE` 에 HTTP 버전(`HTTP/[12].[01]`)을 포함해 매칭하므로 이 환경에서 정상 발동한다.
- `nolog` 라 로그가 남지 않아, 효과를 920350 유무로 간접 확인한다.
