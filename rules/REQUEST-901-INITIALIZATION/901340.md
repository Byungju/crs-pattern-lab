# 901340 — 요청 본문 변수 강제

- **파일**: `REQUEST-901-INITIALIZATION.conf` (line 375)
- **phase**: 1
- **action**: `pass`, `nolog`, `noauditlog`, `ctl:forceRequestBodyVariable=On`
- **로그**: 없음 (nolog + noauditlog)
- **검증**: [`tests/901340.sh`](tests/901340.sh) — 디버그 로그로 확인

## 조건

```
SecRule REQBODY_PROCESSOR "!@rx (?:URLENCODED|MULTIPART|XML|JSON)"
```

`REQBODY_PROCESSOR` 가 URLENCODED/MULTIPART/XML/JSON **어느 것도 아닐 때** 매칭(빈 값 포함).

## 동작

`ctl:forceRequestBodyVariable=On` 으로, 알려진 body processor 가 없는 요청의 본문을
`REQUEST_BODY` 변수로 강제 노출시켜 검사 가능하게 만든다.

## 설명 / 영향

- Content-Type 이 없거나 `text/plain` 등 processor 미지원 타입일 때, 본문을 검사하지 못해
  발생하는 **우회를 완화**한다.
- `tx.enforce_bodyproc_urlencoded=1`(901350)과 함께 쓰면 URLENCODED 로 강제 파싱된다.
- `nolog,noauditlog` 이므로 로그가 남지 않아 디버그 로그 또는 효과로만 확인 가능하다.

## 검증

`nolog/noauditlog` 라 로그가 없으므로 `SecDebugLogLevel 9` 로 룰 평가를 확인한다.
(text/plain body 요청)

```
./tests/901340.sh
LOG  [4] (Rule: 901340) Executing operator "Rx" ... against REQBODY_PROCESSOR.
PASS 901340: REQBODY_PROCESSOR 대상 룰 평가 확인 (debug)
```
