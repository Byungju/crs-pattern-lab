# 911100 — Method is not allowed by policy

- **파일**: `REQUEST-911-METHOD-ENFORCEMENT.conf` (line 28)
- **phase**: 1
- **action**: `block`, `logdata:'%{MATCHED_VAR}'`, `setvar:'tx.inbound_anomaly_score_pl1=+%{tx.critical_anomaly_score}'`
- **severity**: CRITICAL (점수 5)
- **paranoia level**: 1
- **검증**: [`tests/911100.sh`](tests/911100.sh) — **PASS**

## 룰 원문

```
SecRule REQUEST_METHOD "!@within %{tx.allowed_methods}" \
    "id:911100, phase:1, block, msg:'Method is not allowed by policy', \
     logdata:'%{MATCHED_VAR}', ... severity:'CRITICAL', \
     setvar:'tx.inbound_anomaly_score_pl1=+%{tx.critical_anomaly_score}'"
```

## 조건

```
REQUEST_METHOD !@within %{tx.allowed_methods}
```

- `tx.allowed_methods` 는 `crs-setup.conf`(900200) 또는 기본값(901160)으로 설정되며 기본은
  **`GET HEAD POST OPTIONS`**.
- `@within` 은 대상을 공백 구분 목록과 비교한다. `!` 로 부정 → **허용 목록에 없는 메서드**면 매칭.

## 동작

- `block` (어노말리 모드 매크로): `tx.inbound_anomaly_score_pl1` 에 `critical_anomaly_score`(5) 누적.
- phase 2 종료 시 `949110` 이 임계값(기본 5) 초과를 보고 **403 차단**.

## 설명 / 영향

- 정책에 없는 메서드(예: PUT/DELETE/PATCH/TRACE…)로 인한 위험(임의 업로드, 데이터 변경, ACL 우회 등)을
  정책 레벨에서 차단한다.
- 허용 메서드를 늘리려면 `crs-setup.conf` 의 `900200`(`tx.allowed_methods`)을 수정한다.
  - 예: REST API → `PUT PATCH DELETE` 추가.
- 주의: `TRACE`, `OPTIONS`, `POST` 등은 **nginx 가 CRS 도달 전에 405/400 을 반환**할 수 있다.
  (정적 리소스에 대해 nginx 가 먼저 거부) 이 경우 CRS 는 개입하지 않는다.
