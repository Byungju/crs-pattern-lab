# 911011 — P1 구간 게이팅 (탐지 룰 아님)

> **한 줄 요약**: 지금 paranoia level(PL)이 **P1 미만**이면, 이 지점부터 파일 끝(END)까지 **건너뛴다.**

- **파일**: `REQUEST-911-METHOD-ENFORCEMENT.conf`
- **phase**: 1
- **action**: `pass`, `nolog`, `skipAfter:END-REQUEST-911-METHOD-ENFORCEMENT`
- **검증**: [`tests/911011.sh`](tests/911011.sh) — **SKIP(탐지 룰 아님)**

## 무슨 룰인가 (쉬운 설명)

- 공격을 탐지하는 룰이 **아니다**. "룰 실행 순서를 제어"하는 **게이팅(제어) 룰**이다.
- CRS는 룰을 **paranoia level(PL, 1~4)** 로 나눈다. PL이 높을수록 더 민감한 룰이 켜진다.
- 파일은 `PL1 구간`, `PL2 구간` … 식으로 나뉘고, 각 구간 앞에
  "현재 PL이 이 구간보다 낮으면 끝(END)으로 점프" 하는 이 룰이 놓인다.

## 조건 → 동작

- **검사**: `TX:DETECTION_PARANOIA_LEVEL "@lt 1"` → 탐지 PL이 1 미만인가?
- **매칭되면**: `skipAfter:END-REQUEST-911-METHOD-ENFORCEMENT` → 아래 **PL1~4 구간 전체** 를 건너뛴다.

| 항목 | 값 |
|------|-----|
| 트리거 조건 | 탐지 PL < 1 |
| 건너뛰는 구간 | PL1~4 구간 전체 |
| 기본값에서 | 탐지 PL = 1 |

## 911100 과의 관계 / 흐름

- 실제 탐지 룰은 [911100](911100.md) 하나뿐이고, 이 룰은 그 실행 범위를 정한다.
- 기본값(탐지 PL=1)일 때:
  - `911011`/`911012` (PL < 1) → PL이 1이라 **매칭 안 됨** → 통과
  - `911100` (PL1 탐지) → 실행됨
  - `911013` 이상 (PL < 2,3,4) → **매칭되어 PL2~4 구간을 건너뜀** (이 파일의 PL2~4 구간은 비어 있음)

## 검증

탐지 룰이 아니므로 공격 예제 대상이 아니다.

```
./tests/911011.sh
SKIP 911011: PL 게이팅(skipAfter) 보조 룰 — 공격 탐지 대상 아님 (911100 실행 여부 제어)
```
